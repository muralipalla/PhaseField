01 · Deployment choice

Choose the backend before installing

The two programs use the same governing equations, input syntax, material parser, and accepted-state logic. Their linear algebra and execution models are deliberately separate.

Native Windows · SciPy

Use phasefield_crack.py for local development, input preparation, and serial studies on Windows 10 or 11. This backend must run with exactly one MPI rank.

one process SciPy sparse solve PowerShell

Install the Windows backend →

Linux · PETSc/MPI

Use linux_cluster/phasefield_crack_petsc.py for distributed meshes, PETSc nonlinear solves, and collective XDMF/HDF5 output on a workstation or scheduled cluster allocation.

multiple MPI ranks PETSc SNES/SNESVI Bash

Install the Linux backend →

Do not mix the environments

Create one environment per platform from the supplied YAML file. In particular, do not add a pip-built petsc4py to the Linux environment. The Linux launcher compatibility-tests the current MPI with the active Python/PETSc stack and bypasses it in favor of Conda MPI when they cannot run together.

02 · Native Windows

Install the serial SciPy backend

Run these commands in PowerShell from the project root. The checked environment.yml pins Python 3.12 and FEniCSx/DOLFINx 0.11 from conda-forge.

Prerequisites

64-bit Windows

Windows 10 or 11 on an x86-64 workstation.

Miniconda

A current 64-bit Miniconda installation with PowerShell integration.

C++ build tools

Visual Studio 2022 Build Tools with Desktop development with C++ and a current Windows SDK for local form compilation.

  1. Get the source code

    Clone the repository with Git, or download the ZIP archive, extract it, and open PowerShell in the extracted project directory.

    Clone from GitHub
    git clone https://github.com/muralipalla/PhaseField.git
cd PhaseField

  2. Initialize Conda for PowerShell

    Use the Miniconda Prompt once, then close and reopen PowerShell.

    One-time shell setup
    conda init powershell

    If conda activate already works, skip this step.

  3. Create the checked environment

    Open PowerShell in the project root.

    Environment file: environment.yml

    Create once
    conda env create --file environment.yml
conda activate phasefield-fenicsx

  4. Update an existing environment

    Synchronize the named environment after pulling project changes.

    Update and prune
    conda env update --name phasefield-fenicsx --file environment.yml --prune
conda activate phasefield-fenicsx

03 · Linux workstation or cluster

Install the PETSc/MPI backend

Copy or clone the complete project because the Linux backend imports shared constitutive, input, material, and metric modules from the project root. Run installation on a login or development host; run MPI simulations only on a workstation or inside a compute allocation.

Prerequisites

64-bit Linux

A current x86-64 Linux distribution with Bash and standard command-line tools.

Miniconda or Miniforge

Conda initialized for Bash. The supplied environment uses conda-forge only.

Compute allocation

Physical cores matching the requested rank count and, on a cluster, scheduler-approved compute resources.

  1. Get the source code

    Clone the repository with Git, or download the ZIP archive, extract it, and open a Bash shell in the extracted project directory.

    Clone from GitHub
    git clone https://github.com/muralipalla/PhaseField.git
cd PhaseField

  2. Initialize Conda for Bash

    Run once if conda activate is not available, then start a new shell.

    One-time shell setup
    conda init bash
exec bash

  3. Create the ABI-compatible stack

    From the project root, create and activate the MPICH-based environment.

    Environment file: linux_cluster/environment-linux.yml

    Create once
    conda env create --file linux_cluster/environment-linux.yml
conda activate phasefield-fenicsx-linux

    Conda solves DOLFINx 0.11, real-scalar PETSc/petsc4py 3.25, mpi4py, MPICH, and MPI-enabled HDF5 as one compatible stack.

  4. Update an existing environment

    Use the supplied lock-style specification rather than piecemeal package upgrades.

    Update and prune
    conda env update --name phasefield-fenicsx-linux \
  --file linux_cluster/environment-linux.yml --prune
conda activate phasefield-fenicsx-linux

Let the launcher test the complete runtime

Do not install a separate pip petsc4py over this environment. Automatic mode checks MPI_HOME, MPI visible before Conda activation, and Conda MPI without assuming a standard installation path. It verifies communicator size and PETSc/mpi4py agreement before use, and automatically bypasses a failed current MPI. For a complete administrator- provided FEniCSx/PETSc/MPI module, container, or Spack build, select RUNTIME_ENV=active.

04 · Quality gate

Verify before solving

Import checks alone are not sufficient. Exercise form compilation, assembly, the intended linear algebra, communicator placement, and output path before a production run.

Windows serial verification

PowerShell · one rank
conda activate phasefield-fenicsx
python -c "import dolfinx, ffcx, ufl, basix, scipy; print('DOLFINx', dolfinx.__version__); print('FFCx', ffcx.__version__); print('UFL', ufl.__version__); print('Basix', basix.__version__); print('SciPy', scipy.__version__)"
python scripts\verify_fenicsx_install.py

Success ends with FENICSX_INSTALL_OK. The verifier intentionally rejects more than one MPI rank because it tests the native-Windows SciPy path.

Linux collective preflight

Run this inside the same compute allocation and at the same rank count planned for the simulation. Select 2, 4, 16, auto, or any positive rank count; oversized direct requests are reduced to detected capacity unless STRICT_RESOURCES=1 requests a hard failure.

Bash · inspect, then preflight four ranks
bash linux_cluster/run_linux.sh --ranks auto --mpi auto --show-options

PREFLIGHT_ONLY=1 EXPECTED_NODES=1 \
  bash linux_cluster/run_linux.sh --ranks 4

Change --ranks and EXPECTED_NODES together for a different allocation. The preflight checks MPI and PETSc communicator agreement, real-scalar PETSc, distributed KSP and SNESVI solves, rank placement, ghost exchange, and collective XDMF/HDF5 write/read.

Select a nonstandard local MPICH path

MPI_HOME may name the installation prefix, or --mpi may name the executable exactly:

Bash · MPICH 4.2.3 in a user directory
MPI_HOME=/home/palla/Software/mpich-local-install \
  bash linux_cluster/run_linux.sh --ranks auto --mpi auto --show-options

PREFLIGHT_ONLY=1 EXPECTED_NODES=1 \
  bash linux_cluster/run_linux.sh --ranks 4 \
  --mpi /home/palla/Software/mpich-local-install/bin/mpiexec

A compatible local launcher is used. If the probe or full preflight fails, the default Conda workflow retries with Conda MPI. A complete site-built stack should instead be launched with RUNTIME_ENV=active.

05 · Smoke cases

Run the smallest checked case

A smoke case confirms parser, solver, and output plumbing. It is not a mesh- converged fracture result and should not be used for material conclusions.

Windows quick run

Activate the serial environment and run from the project root.

PowerShell
conda activate phasefield-fenicsx
python phasefield_crack.py --quick --output-dir results\quick

For a checked input-file run:

PowerShell · input file
python phasefield_crack.py --input-file inputs\notched_tension.in

Linux variable-rank smoke run

Run only after the collective preflight succeeds.

Bash · one host
conda activate phasefield-fenicsx-linux
RANKS=4
INPUT_FILE=linux_cluster/inputs/cluster_smoke.in \
OUTPUT_DIR="results/smoke_${RANKS}r" \
bash linux_cluster/run_linux.sh --ranks "$RANKS"

On a 16-physical-core Xeon workstation, run the prepared validation suite:

Bash · Xeon16 suite
bash linux_cluster/run_xeon16_suite.sh smoke
bash linux_cluster/run_xeon16_suite.sh validation
SCALING_REPEATS=3 bash linux_cluster/run_xeon16_suite.sh scaling

Installation is complete when

  • The environment activates without import or shared-library errors.
  • The platform verifier completes with its expected rank count.
  • The smoke run reports completion and writes finite CSV/JSON output.
  • Requested XDMF/HDF5 output can be opened from the target filesystem.

06 · Diagnostics

Troubleshooting by symptom

Fix the environment or launcher problem before changing fracture parameters. Preserve the supplied YAML specifications while diagnosing the stack.

conda is not recognized

Start a Miniconda/Miniforge prompt, run the platform's conda init command once, then open a new shell. Confirm that conda info succeeds before creating the environment.

Windows DLL or JIT failure

Activate phasefield-fenicsx in the current PowerShell. Confirm the C++ workload and Windows SDK are installed, then rerun the serial verifier. Do not invoke a different base Python executable.

Linux rank or communicator mismatch

Run MPI_PROBE_VERBOSE=1 bash linux_cluster/run_linux.sh --ranks auto --mpi auto --show-options. It reports the current and Conda candidates, physical-core/allocation capacity, and the final selection. A failed current-MPI probe normally causes automatic Conda fallback. Reserve FORCE_INCOMPATIBLE_MPI=1 for deliberate expert diagnosis; legacy ALLOW_EXTERNAL_MPI=1 is accepted but no longer needed.

Ranks placed on the wrong nodes

Request resources through the site scheduler and set expected ranks/nodes to the allocation. Use the supplied Slurm or PBS template as a starting point; queue, account, and launcher flags remain site-specific.

Collective XDMF/HDF5 failure

Use a path visible at the same location to every rank. Prefer shared scratch for multi-node output, verify it with --check-xdmf, and copy completed results to long-term storage afterward.

Smoke passes but a study fails

This is usually a model-resolution or nonlinear-convergence issue rather than installation. Check mesh-to-length-scale resolution, load increments, boundary conditions, material ranges, and solver diagnostics in the model guide.

Cluster policy takes precedence

Do not run MPI simulations on an institute login node. Follow the local scheduler, module, filesystem, and software policy. If the site supplies a tuned PETSc/FEniCSx stack, validate it with the included preflight before use.
