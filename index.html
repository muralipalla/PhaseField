02 · Native Windows

Windows serial installation

Open PowerShell in the project root. The checked environment.yml supplies Python 3.12, FEniCSx 0.11, SciPy, and the output/visualization dependencies.

Prerequisites

Operating system

64-bit Windows 10 or 11.

Conda

Current 64-bit Miniconda with PowerShell integration.

Compiler

Visual Studio 2022 Build Tools, Desktop development with C++, and a current Windows SDK.

  1. Get the source code

    Clone the repository with Git, or download the ZIP archive, extract it, and open PowerShell in the extracted project directory.

    PowerShell · clone
    git clone https://github.com/muralipalla/PhaseField.git
cd PhaseField

  2. Create and activate

    If needed, run conda init powershell once in the Miniconda Prompt and reopen PowerShell.

    Environment file: environment.yml

    PowerShell · create once
    conda env create --file environment.yml
conda activate phasefield-fenicsx

  3. Update an existing environment

    PowerShell · synchronize
    conda env update --name phasefield-fenicsx --file environment.yml --prune
conda activate phasefield-fenicsx

  4. Verify imports, assembly, and solve

    PowerShell · one-rank verifier
    python -c "import dolfinx, ffcx, ufl, basix, scipy; print('DOLFINx', dolfinx.__version__); print('SciPy', scipy.__version__)"
python scripts\verify_fenicsx_install.py

    Success ends with FENICSX_INSTALL_OK. This verifier intentionally rejects multiple MPI ranks.

  5. Run the checked quick case

    PowerShell · smoke run
    python phasefield_crack.py --quick --output-dir results\quick

    Then use inputs/notched_tension.in for the documented input-file workflow.

03 · Linux workstation or cluster

Linux PETSc/MPI installation

Run environment creation from the project root. Run the preflight and simulation on a workstation or inside a scheduler-approved compute allocation, never on an institute login node.

Prerequisites

Operating system

Current 64-bit Linux with Bash and standard command-line tools.

Conda

Miniconda or Miniforge initialized for Bash.

Resources

Physical cores matching the MPI ranks and, on a cluster, an active compute allocation.

  1. Get the source code

    Clone the repository with Git, or download the ZIP archive, extract it, and open a Bash shell in the extracted project directory.

    Bash · clone
    git clone https://github.com/muralipalla/PhaseField.git
cd PhaseField

  2. Create the compatible MPI/PETSc stack

    If needed, run conda init bash once and start a new shell.

    Environment file: linux_cluster/environment-linux.yml

    Bash · create once
    conda env create --file linux_cluster/environment-linux.yml
conda activate phasefield-fenicsx-linux

  3. Update an existing environment

    Bash · synchronize
    conda env update --name phasefield-fenicsx-linux \
  --file linux_cluster/environment-linux.yml --prune
conda activate phasefield-fenicsx-linux

  4. Verify all 16 ranks and collective I/O

    Change ranks and nodes together when the intended allocation differs.

    Bash · 16 ranks on one host
    mpiexec -n 16 python -u linux_cluster/check_environment.py \
  --expected-ranks 16 --expected-nodes 1 \
  --check-xdmf results/preflight_16r

    The preflight exercises MPI/PETSc communicator agreement, KSP, SNESVI, placement, ghost exchange, and parallel XDMF/HDF5.

  5. Run the small parallel smoke case

    Bash · 16 ranks
    NPROCS=16 \
INPUT_FILE=linux_cluster/inputs/cluster_smoke.in \
OUTPUT_DIR=results/smoke_16r \
bash linux_cluster/run_linux.sh

  6. Validate a 16-core Xeon workstation

    Bash · functional and scaling suites
    bash linux_cluster/run_xeon16_suite.sh smoke
bash linux_cluster/run_xeon16_suite.sh validation
SCALING_REPEATS=3 bash linux_cluster/run_xeon16_suite.sh scaling

Keep the entire MPI stack ABI-compatible

The supplied environment solves MPICH, mpi4py, real-scalar PETSc/petsc4py, DOLFINx, and MPI-enabled HDF5 together. Do not install a separate pip petsc4py or use an unrelated system mpiexec. For tuned multi-node fabrics, ask the administrators for their consistent FEniCSx/PETSc module, container, or Spack workflow.

04 · Diagnostics

Troubleshoot the stack first

Fix environment, compiler, launcher, or filesystem problems before changing fracture parameters. Recreate from the supplied YAML if a stack was modified piecemeal.

conda is unavailable

Start a Miniconda/Miniforge prompt, run conda init powershell or conda init bash, and open a new shell.

Windows DLL or JIT error

Activate phasefield-fenicsx in the current PowerShell. Confirm the Visual Studio C++ workload and Windows SDK, then rerun the serial verifier.

MPI rank or communicator mismatch

Inspect which python and which mpiexec. Both must resolve to one compatible MPI stack and match the requested allocation.

XDMF/HDF5 write failure

Use a path visible at the same location to every rank. Verify shared scratch with --check-xdmf before production output.

Smoke passes, study fails

Check mesh-to-length-scale resolution, load increments, boundary conditions, material ranges, and solver diagnostics in the verification guide.

Need a site-specific launcher

Start from the supplied Slurm/PBS templates, then set the local account, queue, nodes, tasks, wall time, and filesystem paths.

Ready for a study when

  • The selected environment activates without import or shared-library errors.
  • The platform verifier succeeds at the intended ranks and nodes.
  • The smoke case completes with finite CSV/JSON output.
  • Requested XDMF/HDF5 output opens from the target filesystem.
